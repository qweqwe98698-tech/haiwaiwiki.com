Clash 系客户端里有两组概念经常被混为一谈,搞混了就会出现
「明明选了全局还是打不开」或者「开了 TUN 反而断网」这类问题。
这一页把它们拆开讲。

## 两组概念,回答两个问题

| 概念组 | 回答的问题 | 选项 |
| --- | --- | --- |
| **分流策略** | 哪些流量走代理? | 规则 / 全局 / 直连 |
| **接管方式** | 流量怎么交给客户端? | 系统代理 / TUN |

**两组必须同时设置正确**。最常见的新手故障就是分流选好了、接管方式没开——
表现为节点测速正常但浏览器打不开网页,完整排查见
[能测速但打不开网页](/tutorial/connected-but-no-internet/)。

## 分流策略:三种模式

### 规则模式(日常默认)

按配置里的规则表逐条匹配:国内域名和 IP 直连,国外走代理,广告域名可能被拒绝。
规则通常由机场订阅提供,更新订阅会同步更新规则。

### 全局模式

不做匹配,所有流量都走当前选中的节点。**它的正确用途是排查**:

> 某网站打不开 → 切全局 → 能打开 = 规则漏了这个域名;还是不行 = 不是规则问题。

不建议长期使用:国内网站绕道海外会变慢,还会多消耗流量。

### 直连模式

所有流量都不走代理,相当于临时停用,但保持客户端运行。

## 接管方式:系统代理与 TUN

### 系统代理

客户端把自己的本地端口写进操作系统的代理设置,读取该设置的程序就会走代理。
**绝大多数浏览器和常见软件都读它**,所以日常够用。

局限:**不读系统代理设置的程序不受影响**。命令行工具、部分桌面软件和游戏属于此类,
典型现象是浏览器正常但它们连不上。

### TUN 模式

TUN 创建一块虚拟网卡,在**网络层**接管全部流量,不管程序读不读代理设置。
它能解决系统代理覆盖不到的场景,代价是要求更高:

- 需要**管理员/root 权限**;
- 需要虚拟网卡驱动正常安装;
- 与部分安全软件、虚拟机网络可能冲突。

### 常用组合

| 场景 | 组合 |
| --- | --- |
| 日常上网 | 规则 + 系统代理 |
| 命令行/游戏等程序要走代理 | 规则 + TUN |
| 排查某网站打不开 | 全局 + 原接管方式 |
| 临时停用 | 直连,或关闭系统代理 |

## 混合端口是什么

混合端口指同一个本地端口同时接受 HTTP 和 SOCKS5 连接。
需要手动填代理地址的软件(如某些开发工具)填这一个端口即可,不用区分类型。
默认端口号在客户端设置里可以看到和修改——端口被其他程序占用时,改一个即可。

## TUN 开启后断网的排查

按这个顺序:

1. **先关掉 TUN**,回到系统代理模式,确认基础功能正常
   (排除是节点或订阅的问题);
2. **以管理员权限重启客户端**——权限不足是最常见原因;
3. **重新安装虚拟网卡组件**(客户端设置里通常有相关按钮);
4. **检查安全软件**是否拦截了虚拟网卡的创建;
5. 仍不行就继续用系统代理模式——多数人其实用不到 TUN。
