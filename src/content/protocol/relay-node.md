faq:
  - q: 入口和落地分别是什么意思?
    a: 入口是你的设备实际连上的第一台服务器(通常在国内或离你很近),落地是最终访问目标网站时使用的那台服务器,决定你的出口 IP。两者之间的链路质量,是中转方案的核心价值所在。
  - q: 中转一定比直连快吗?
    a: 不一定。中转多了一跳,如果中间链路本身质量一般,总延迟可能比直连更高。中转的优势在稳定性——尤其是晚高峰,优化过的入口链路波动更小。
  - q: 中转和专线是一回事吗?
    a: 不是同一层的概念。中转描述的是结构(拆成两段),专线描述的是中间那段用什么链路。中转可以走专线,也可以走普通公网隧道,后者常被称为公网中转。
  - q: 为什么中转节点的倍率更高?
    a: 多了一台入口服务器和一段链路成本,尤其走专线时成本明显更高。机场通过倍率把这部分成本分配给实际使用者,倍率机制见本站对应词条。
  - q: 落地 IP 决定什么?
    a: 决定目标网站看到的是哪个国家、哪种类型的 IP,也就决定了流媒体和 AI 服务的解锁情况。入口在哪里不影响这一点,别把两者混淆。
  - q: 直连节点适合什么人?
    a: 网络环境本身对目标地区路由较好、或者主要在非高峰时段使用的人。直连链路简单、故障点少,在条件合适时体验很好,成本也更低。

看机场节点列表时,你会遇到「中转」「入口」「落地」这几个词。
它们描述的是**连接的结构**,而不是速度或质量本身。搞清楚结构,
才能判断商家的宣传说的是哪一层。

## 直连与中转:两种结构

**直连**:你的设备 → 海外服务器。一跳到位,链路最简单,
完全依赖你所在网络到该服务器的公网跨境质量。

**中转**:你的设备 → 入口服务器 → 落地服务器 → 目标网站。
把一次跨境连接拆成两段:

- **入口**(也叫中转服务器):你实际连上的第一台机器,通常在国内或离你很近。
  它的作用是让「你到入口」这一段走质量可控的路径;
- **入口到落地**:这一段是方案的关键,可以走
  [IEPL/IPLC 专线](/protocol/iplc-vs-iepl/),也可以走普通公网隧道;
- **落地**:最终访问目标时使用的服务器,**它的 IP 就是你的出口 IP**。

## 为什么要多这一跳

跨境公网的质量波动主要发生在出境段。中转的思路是:
既然这段路不可控,那就用**可控的链路**替代它。

- 入口段走运营商优化过的路由,减少绕路和拥堵;
- 入口到落地如果是专线,则完全避开公网跨境的拥堵点;
- 多入口设计还能让不同运营商的用户各自连最优入口
  (这就是「三网优化」这类宣称的技术来源)。

代价也很直接:多一台服务器、多一段链路,**成本更高**,
所以中转节点的[倍率](/protocol/node-multiplier/)通常也更高。

## 中转不等于专线

这是最容易混淆的一点:

| 概念 | 描述的是 |
| --- | --- |
| 中转 / 直连 | 连接的**结构**(几段) |
| 专线 / 公网 | 中间那段用**什么链路** |

所以「公网中转」和「专线中转」都是中转,体验差别却很大——
前者仍然要挤公网跨境,后者不用。商家只说「中转」而不说链路类型时,
默认按公网中转理解比较稳妥,判断方法见[专线机场推荐](/airport/dedicated-line/)。

## 落地决定解锁,入口不影响

一个实用结论:**能不能看 Netflix、能不能用 ChatGPT,由落地 IP 决定**,
和入口在哪、走不走专线无关。

所以会出现这种情况:一个走专线、晚高峰很稳的节点,却打不开 ChatGPT——
因为它的落地 IP 质量不行。两件事要分开看,IP 那一层见
[原生 IP 词条](/protocol/native-ip/)。

## 怎么选

- **在意晚高峰稳定** → 优先中转 + 专线,见[稳定机场推荐](/airport/stable/);
- **在意解锁能力** → 看落地 IP 类型,别只看线路宣传;
- **在意成本** → 注意中转节点的倍率,日常浏览可以用低倍率的普通节点;
- **网络环境本身到目标地区路由不错** → 直连节点简单、故障点少,值得一试。

节点名里通常能看出线索:标注了地区 + 专线/IEPL 的多为中转专线,
只标地区的可能是直连或公网中转——不确定时问客服,这也是本站在
[机场档案库](/directory/)里把线路细节列为已知限制的原因。
