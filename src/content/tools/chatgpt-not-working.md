先明确问题类型:本文处理的是**代理本身正常**(能开 Google/YouTube),但 ChatGPT
打不开、提示地区不可用、或反复人机验证的情况。如果所有网站都打不开,
那是连接问题,请先看 [Clash 教程的排错部分](/tutorial/clash-import-subscription/)或
[延迟分层排查](/airport/high-latency/)。

## 先理解原因结构,排查才有顺序

ChatGPT 的访问限制发生在两层:**地区**(服务不对某些地区开放)和
**IP 风控**(对数据中心 IP、已知代理出口、滥用历史 IP 段的限制)。
机场用户遇到的问题绝大多数出在第二层——你用的节点 IP 已经被标记。
这就是为什么下面的排查从换节点开始,而不是从重装应用开始。

## 六步排查(按命中率排序)

### 1. 换节点,优先带「解锁 / GPT / 流媒体」标注的

机场通常只有部分节点用了 IP 质量较好的出口,并在节点名里标注。
普通节点连 ChatGPT 被拒是常态,不是故障。为什么 IP 质量起决定作用,
见[原生 IP 词条](/protocol/native-ip/)——看完你会明白「换机场」经常是不必要的。

### 2. 确认节点地区受支持

OpenAI 的服务地区列表不含中国大陆、香港、俄罗斯等。香港节点开 ChatGPT 必然失败——
这是新手最常踩的坑:离得近的节点反而不能用。换美国、日本、新加坡等受支持地区的节点。

### 3. 清 Cookie 再试

服务端会记住你上一次的风控判定。换了节点仍提示地区错误时,
清除浏览器里 chatgpt.com 与 openai.com 的 Cookie(或直接用无痕窗口验证),
让服务端基于新 IP 重新判断。

### 4. 检查分流规则

客户端规则不全时,OpenAI 的部分域名可能被直连,表现为页面能开但登录/对话异常。
临时把客户端切到**全局代理**模式验证:全局下正常 = 规则问题,
更新订阅或补全 OpenAI 相关域名规则;全局下依旧 = 回到第 1 步,还是 IP 的问题。

### 5. 排除浏览器因素

个别插件(隐私类、指纹修改类)会触发额外风控。无痕窗口 + 禁用插件测一次,
排除本地因素。

### 6. 以上全试过:向机场求证或换服务

带着你的排查结果(哪些节点、什么表现)去问机场客服,通常能得到「哪些节点当前可用」的直接答案。
客服失联或长期没有可用节点,那就是[重新选机场](/airport/how-to-choose/)的时机了——
选择时把「AI 可用性」列为首要维度,并留意[风险信号](/risk/exit-scam-signals/)。

## 为什么本文不提供「保证可用」的节点或服务

IP 风控每天都在变,任何「保证解锁」的静态承诺都会过期。
本站的原则是给你判断与排查的方法,而不是给一个很快会失效的答案——
这也是[编辑规范](/about/editorial/)里「不写无法验证的承诺」的具体体现。
